## 建议的本机演练验收

先安装开发依赖，并运行自动化测试。然后在独立数据目录启动演练，保留日志和数据库。

```powershell
& '.\.venv\Scripts\python.exe' -m pytest -q
& '.\.venv\Scripts\python.exe' -m opssentinel --host 127.0.0.1 --port 8765 --data-dir work/validation-data --demo
```

逐个注入 `bad_release`、`bad_config`、`process_exit`、`log_pressure`，等待上一个事件恢复后再进行下一项。每项检查：连续失败才建单、证据对应故障、动作在允许集合内、动作后重新探测、达到连续健康阈值才恢复。

审批路径使用未自动授权的服务，检查审批前不执行，审批后重新探测，重复审批不重复动作。忽略事件必须留下理由和记录，不计为恢复。服务关闭后不应继续自动扫描。

## 恢复与负面用例

| 场景 | 应检查的行为 |
| --- | --- |
| 探测超时或连接器报错 | 记录失败，调度器仍能处理其他服务 |
| 模型不可用、输出无效动作或指令注入 | 规则回退或等待处理，不执行任意命令 |
| 控制器在动作途中退出 | 重启后保留不确定状态，不盲目重放 |
| 代理重复收到同一 `operation_id` | 返回已知结果或不确定状态，不重做副作用 |
| 无 Token 访问受保护 API | 返回认证错误，健康端点仍可检查 |
| 无自定义请求头的状态改变请求 | 拒绝请求 |
| 代理目标不在允许列表、回滚配置不足 | 拒绝执行并说明原因 |
| 恶意 HTML 日志 / 服务名称 | 看板显示纯文本 |
| 演练端口被其他进程使用 | 不终止无关进程 |

## 评价指标

统计误报率、实际恢复率、探测到恢复的耗时、每事件动作次数、重复事件数量、需要人工处理的比例，以及模型启用时的费用。恢复率应单独区分演练、测试环境和真实服务；未做真实验证时，不报告生产成功率。
